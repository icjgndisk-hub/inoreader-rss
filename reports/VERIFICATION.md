# 実サイト検証・受入状況（2026-10-20）

## 現時点の判定

4サイトの実データ収集、画像補完、RSS生成、再取得時の履歴保持は動作した。詳細な件数は `acceptance-evidence.json` と `latest-run.json`、実URLの応答は `live-sample-audit.json` に記録している。クラウド公開状況とInoreaderでの実表示は `DEPLOYMENT.md` を参照。**Inoreaderの週刊アスキーの画像を実画面で確認するまでは、最重要条件の受入完了とはしない。**

現在採用している取得経路は4サイトともサーバーから返るHTML/XMLで収集でき、JavaScriptブラウザの常時実行は不要。信毎の「もっと見る」はこの版では操作せず、サイトマップで補完する。公式RSSが世界中のどこにも存在しない、と断定するものではない。

### 週刊アスキーの画像

元RSSには60×60の小画像や `type` と `length` がないenclosureがあった。生成版は記事固有OGP/一覧の大きい画像を採用し、media:thumbnail、media:content、descriptionのimg、content:encodedを併記する。MIMEと長さを確認できた画像のみ正しいenclosureを出す。

これは観測した不備への対策であり、旧フィードがInoreaderで表示されなかった唯一の原因と断定していない。実画像の標本はHTTP 200、300×200または600×400でPillowの画像検証に成功。標本中2件は一覧用 `/m/` のため記事OGPの `/l/` とURLが異なる。記事と対応する一覧画像を使っている。Inoreader側の抽出・プロキシ・既存キャッシュについては実表示で確認が必要。

### 号外NETの「利用できる記事がありません」

本環境ではRSSに10記事があり、XML・feedparserで読めた。最新の**公開日時**は2026-09-03 18:07:59 JST、次の記事は2026-02-28で、トップ・記事のdatePublishedとも整合する。最新記事には10月の更新情報/画像があっても、公開日を10月に置き換えない。

したがって、少なくとも今回の取得では「RSSが空」は該当しない。古い記事しかないこと、Inoreaderの表示フィルターやキャッシュなどが関係する可能性はあるが、利用者の実画面を見ずに原因を確定できない。生成版は一覧を遡り500記事を配信する。

## 実データで確認した範囲

- 個別4フィード各500件、統合1000件。UTF-8 XML、RSS 2.0必須項目、RFC形式の日時、GUID重複なし、feedparserのbozoなし。
- 初回取得の保存URL集合と再実行後を比較し、全サイトで既存履歴の欠落0件。500件より古い履歴もstateへ残る。
- 同一URLのタイトル・画像更新は同じGUIDになる。日付のみ/分単位/秒単位を区別し、低精度の一覧で高精度の公開日時を失わない。
- 最終の通常再取得では各サイト15画像を新たに検査し、15/15成功。画像URLを持つ全500件を毎回実ダウンロードしたわけではない。
- 各サイト3件、計12件の標本で元記事HTTP取得と画像ファイル全体のPillow検証に成功。写真を納品物へ複製していない。標本は「HTTP検証済みの最新3件」であり、無作為標本や全件成功率ではない。
- テスト29件成功。実HTMLの最小fixtureによる4サイト別抽出、robots、429/503再試行、日付保持、画像失敗後の再試行、ページ送り回復、履歴破損検出、XMLエスケープを含む。
- 収集途中の中断でも発見URLと途中の補完結果をcheckpoint保存し、再開時に読み込めた。クラウドでの再実行証拠はDEPLOYMENT.mdへ別記する。

「画像URLありの割合」「画像URLのHTTP検証済み件数」「Inoreaderで見えた割合」は別の指標。信毎には写真なし記事もあり、共通ロゴを付けて100%にはしない。サイト全体の総記事数が既知ではないため、全新着記事の網羅率を100%とは報告しない。

## robots・利用条件・外部画像

- 各取得先のrobots.txtを読み、該当するルールを守る。週刊アスキーはSitemap宣言、号外NETは主にwp-admin、伊那谷は主にadminの制限を確認した。
- 信毎には特定のAIクローラー名への拒否規則がある。このプログラムは識別可能なPersonalNewsRSS User-Agentを使う個人購読用収集で、該当するルールに従う。全データの学習・本文転載は目的としない。
- image.shinmai.co.jpのrobots.txtは403だったが、実画像は200。RFC 9309 §2.3.1.3に基づきrobotsの4xxを未提供として扱う。画像本体の403を回避する機能はない。
- 週刊アスキーのサイトポリシー、伊那谷のcopyright/externalを確認。号外NET・信毎の再配信全般に関する詳細条件は十分に確認できておらず、明示的な再配信許諾を得たとは扱わない。公開情報へのリンクとメタデータに限定する。
- 確認した画像標本はリファラー偽装なしで応答した。これは将来の外部参照やInoreader画像プロキシからの取得を保証しない。外部参照が拒否されれば、その画像は除外・再試行し、プロキシ再配布で回避しない。

## 無料構成の選定と残る制約

GitHub Actions＋Pagesを採用。スケジュール、公開HTTPS、Gitによる履歴を同一サービスで管理でき、公開リポジトリの標準ランナーを使える。別のWorker/DB/ストレージ構成ではサービス別の設定と容量管理が増えるため今回は採用しなかった。各社無料枠が永続不変とは保証しない。

収集は15〜30分を目標とするがActionsに遅延・実行欠落があり、Inoreader無料版の巡回もこの間隔に固定できない。長期停止してサイト側の一覧/サイトマップから消えた未発見記事は回収できないことがある。保存履歴は削除しないため、数年単位ではファイル分割等の保守が必要。正確な公開時刻のない伊那谷ではその時刻を復元できない。

`deploy.ps1` は任意のWindows導入補助。Windows上での実行は未検証。READMEのブラウザ手順と、実際のクラウド配置結果を優先する。

## 証跡

- `acceptance-evidence.json`: RSS件数、画像件数、日付精度、履歴集合比較
- `latest-run.json`: 最終のサイト別取得数・試行数・エラー・取得範囲
- `live-sample-audit.json`: 実記事/画像のURL・HTTP・寸法・日時
- `tests.txt`: テスト実行ログ
- `retrieval-manifest.json`: 調査に用いた実レスポンスのサイズとSHA-256（全文HTMLは非同梱）
- `tests/fixtures/`: 広告や記事全文を取り除いた実構造の最小fixture
- `DEPLOYMENT.md`: 公開・Inoreader受入の状態
